# ADR-002. Унификация интерфейса провайдеров моделей (ModelProvider API)

Дата: 2026-08-25. Статус: принято.

## Контекст и проблема
Продуктовое ТЗ (§6.4 «Model Router») предлагает интерфейс провайдера из четырех методов:
`generateText()`, `streamText()`, `toolCall()`, `structuredOutput()`.

## Решение
Интерфейс `ModelProvider` сокращен до трех базовых методов:
1. `generate(input: ModelInput, signal?: AbortSignal): Promise<ModelOutput>`
2. `stream(input: ModelInput, signal?: AbortSignal): AsyncIterable<ModelEvent>`
3. `countInputTokens(input: ModelInput): Promise<number>`

Вызовы инструментов (`toolCall`) и структурированный вывод (`structuredOutput`) реализуются следующим образом:
- **Инструменты**: Вызов инструмента не является отдельным типом сетевого запроса, а представляет собой один из штатных результатов обычной генерации (`ContentPart` с типом `tool_use` и `stopReason: 'tool_use'`). Выделение отдельного метода `toolCall()` создало бы дублирующий путь исполнения с собственными ошибками и расхождениями в учете токенов.
- **Структурированный вывод (`structuredOutput`)**: Реализуется как надстройка над `generate()` в модуле `src/structured.ts`. Схема передается как единственный доступный инструмент с принудительным выбором (`toolChoice: { name }`), а полученный аргумент валидируется Zod-схемой. Такой подход обеспечивает 100% идентичное поведение у всех поддерживаемых провайдеров (Anthropic, OpenAI, Google) без зависимости от различий в их нативных JSON-режимах.

## Последствия
- Единый унифицированный конвейер вызова, валидации, ретраев и учета стоимости в `executeModelCall`.
- Отсутствие дублирования кода конвертации и обработки ошибок между текстовыми и инструментальными запросами.
- Детерминированная валидация структурированного вывода на уровне вызывающего кода.
