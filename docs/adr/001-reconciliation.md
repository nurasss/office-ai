# ADR-001. Сведение продуктового ТЗ (TZ_AI_Company_OS v1.0) с инженерными конвенциями

Дата: 2026-08-25. Статус: принято.

## 1. Оркестратор: собственный, не LangGraph
ТЗ §13 рекомендует граф-ориентированный оркестратор «по типу LangGraph», но явно
оставляет решение архитектурному ревью.
Решение: пишем собственный Task Engine с семантикой LangGraph (StateGraph, checkpointer,
interrupt для HITL), без самого LangGraph.
Обоснование: (а) стек Node/TypeScript, LangGraph зрелее в Python; (б) §17 объявляет
оркестрацию частью moat платформы, отдавать её во внешний фреймворк противоречит
собственному принципу; (в) требования §6.11 (бюджеты 4 уровней), §6.8 (Permission Broker)
и §6.10 (полный трейсинг) всё равно пришлось бы писать поверх фреймворка.
Обязательство: реализовать checkpoint/pause/resume/interrupt не хуже, чем в LangGraph,
иначе решение пересматривается.

## 2. services/ реализуются как packages/
ТЗ §8.2 задаёт отдельный каталог `services/` (model-router, memory-engine,
execution-engine, agent-runtime, notification-service).
Решение: до Фазы 7 это библиотеки в `packages/`, разворачиваемые через `apps/api`
и `apps/worker`. Границы модулей соблюдаются, чтобы вынос в отдельные сервисы был
механическим. Каталоги `skills/` и `infrastructure/` создаются как в ТЗ.
Обоснование: пять сетевых сервисов в MVP дают распределённую отладку без выигрыша.

## 3. Навыки, инструменты и модели — нормализованные таблицы
ТЗ §9.1 перечисляет agent_models, agent_skills, agent_tools; §6.1 показывает их же
как массивы внутри JSON агента.
Решение: хранение нормализованное (каталог + связь many-to-many), API отдаёт агента
в форме из §6.1, собирая вложенные поля. Каталог инструментов несёт autonomy_level
(§6.8), каталог навыков нужен для Skill Marketplace (§14, Phase 4).

## 4. Схема БД строится инкрементально
ТЗ §14 ставит «PostgreSQL schema» первым пунктом, §9.1 перечисляет ~25 таблиц.
Решение: имена и состав таблиц фиксируются по §9.1, но создаются по мере появления
использующей их логики. Таблицы под неспроектированную логику не заводятся.

## 5. Python-воркеры отложены
ТЗ §16 указывает «Workers: Node.js + Python». До Фазы 7 (sandbox) воркеры только на Node.
Python появляется внутри песочницы исполнения, а не как второй рантайм платформы.
